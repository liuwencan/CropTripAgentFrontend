# UI 模式选型（UI Pattern Selection）

按场景选择正确的组件与交互模式。先读本文件（决策框架 + 高频内联决策表），低频决策按文末索引读 references。

## 0. 决策框架

### 0.1 决策链（5 步闭环）

**场景 → 约束 → 组件 → 选型规则 → 验证**

1. 先答"这个组件要解决什么用户任务"，没有明确任务的组件不要加。
2. 约束优先级：**用户指定规范 > 与旧页一致性 > 通用决策表**。
3. 选型规则：见各 references 决策表；规则冲突时按约束优先级仲裁。
4. **验证（交付前必做）**：见 0.4 检查清单。
5. **入口协议（任务→决策点）**：先拆解任务为决策点清单（如"用户列表页"→ 布局/表格/分页/操作列/三态/权限/接口），逐个走对应决策表，不跳步。
6. **回退协议**：决策表匹配不到场景 → 用最接近的规则 + 按 0.5 问用户，不硬套。
7. **决策锚点**：每条规则隐含"为什么"（依据在各章锚点）；推理表外场景以依据为准，必要时查权威源（Material 3 / NN/g / AntD）。
8. **交付物**：每次决策输出 = 选了什么 + 为什么（可审）+ 代码骨架 + 检查清单回执。让用户能审决策，而非只看结果。
9. **变更成本提示**：新决策与既有实现冲突（如表格→卡片、Modal→Drawer）时，提示重构成本并让用户确认（0.5），不擅自推翻既有实现。评估方法：搜索受影响组件/样式的全部引用处，按影响面大小提示。

### 0.2 边界声明

本技能管**组件选型与决策**（选什么、什么时候用、为什么）。工程实现细节（怎么写组件、怎么封装请求、怎么写样式）见 `frontend-ui-engineering` 技能。两者同时加载时职责不重叠。**何时不加载本技能**：纯后端任务、纯算法/数据处理任务、无 UI 输出的任务。实现层技能缺失时，回退通用工程实践（组件拆分/状态管理/样式组织），不因缺实现技能而停摆。

**引用格式**：内联章节用 §N.N（如 §3.2）；references 文件用文件名（如 guardrails.md）。

### 0.3 触发场景

触发任务：构建/改造页面或界面；选择组件（按钮/下拉/输入/弹窗/图表/表格/导航/进度条）；设计表单与校验；登录页/官网首页/首屏设计；接口对接与数据获取；路由/权限/状态管理选型；深色模式/主题/i18n；双端适配；与既有页面风格一致或遵循某规范。

**负向边界**：纯后端、纯算法、无 UI 输出的任务**不加载**。

### 0.4 交付前检查清单（验证步，全部 🔴）

| 维度 | 检查项 |
|---|---|
| 三态 | 每个数据区都有 加载/错误/空 三态（含局部失败），无空白屏/无限 loading |
| 表单 | 必填/格式/业务校验齐；校验规则与后端契约一致；提交中防重复 |
| 无障碍 | 键盘可达；图标按钮 aria-label；弹窗焦点管理；对比度 4.5:1；颜色非唯一指示；动态区 aria-live |
| 安全 | 无 v-html 渲染用户输入；token 存储符合 guardrails 方案；上传双端校验 |
| 一致性 | token 与既有页面一致；组件库与变体对齐 |
| 性能 | 大列表虚拟化；图片懒加载；动效 ≤200ms |
| 反馈 | 破坏性操作有确认/可撤销；异步操作有进度/结果反馈 |

### 0.5 问用户规则（必须带选项问，不擅自决定）

1. 规范/风格未指定，且无旧页面可参考 → 问：风格方向（提供 2~3 个选项）
2. 接口无法复用（见 api.md）→ 问：扩展后端 / 新建接口（给契约草案）/ 用户决定
3. 破坏性设计决策（大改配色/主题/布局重构）→ 问：确认后再动手
4. 需求模糊（"做个好看的页面"但没给目标/受众）→ 问：先澄清目标与受众

**决策记录**：问用户的答案（约束模式/接口选择/风格方向）在当前会话内**显式记录并应用到后续相关页面**；**默认只作用于本次任务/该页面**，用户说"全站"才扩散；会话内不变，跨会话靠记忆系统。

### 0.6 规则级别

| 级别 | 含义 | 示例 |
|---|---|---|
| 🔴 MUST | 硬红线，任何情况不违反（安全/无障碍/数据安全） | v-html 禁渲染用户输入、对比度 4.5:1 |
| 🟡 SHOULD | 通用启发，可被用户指定规范/一致性覆盖 | 主按钮 ≤1、饼图 ≤5 类 |
| ⚪ MAY | 可选手法，按场景决定 | 液态玻璃、滚动收缩、何时不做 hero |

**约定**：未标注 = 🟡；guardrails.md（无障碍/安全）全 🔴；**用户即时指令 > 规范 > 一致性 > 通用**（🔴 不可被覆盖）。

### 0.7 快速模式（原型/赶工）

用户要"快"时启用：跳过装饰性决策（美化/动效/双端细节），**只保 🔴 安全红线 + 三态 + 可运行**；交付时声明跳过了什么，供后续补齐。

## 3. 操作组件

### 3.1 按钮

| 场景 | 规则 |
|---|---|
| 层级 | 主操作=实心面状（**同一时刻可见 ≤1**，至多 2，放视觉焦点位）；次要=线状（≤主操作数）；最轻=文字（列表行内操作）；危险=红色+二次确认。**长页滚动 CTA 例外**：同一目标的重复入口，不同屏各一个可接受 |
| 状态 | 禁用要可读（别低对比灰）；异步=按钮内 spinner+**防重复点击**（此处为唯一权威定义）；图标按钮必有 tooltip/aria-label |
| 链接 vs 按钮 | 导航→链接（可中键新开）；动作→按钮；视觉别混 |
| 图标 vs 图标+文字 | 高频操作/语义模糊 → 图标+文字；低频/图标语义明确 → 纯图标 |

**锚点**：主操作唯一 = 不稀释层级、避免决策瘫痪；危险红色+确认 = 删除/覆盖不可逆；禁用灰保持可读 = 用户需要知道"有这东西但不能点"。

### 3.2 下拉组件

| 组件 | 使用场景 | 坑 |
|---|---|---|
| Select（单选） | 选项 7~20 个或空间紧 | ≤7 用 Radio 组更直接；键盘导航（上下键/ESC 关闭） |
| Multi-Select（多选） | 多选且选项多 | 选中项 tag 回显；全选/清空快捷 |
| Grouped Select | 选项有明确类别 | 用 optgroup；分组 ≤5 |
| Cascader | 层级联动（地区/分类） | 回显完整路径；深层级考虑 TreeSelect |
| Split Button | 主操作+变体（保存/另存为） | 变体放下拉；主按钮保持主样式 |
| Mega Menu | 大型导航（见 pages.md） | 别塞全站地图 |

**何时不用下拉**：二选一→Switch；单选 2~5→Radio；多选少量→Checkbox。只有"选项多/空间紧"才用下拉。

### 3.3 菜单 / 分页 / 滚动

| 场景 | 规则 |
|---|---|
| 菜单 Menu | 页面导航→常驻菜单；临时操作分组→下拉菜单；行内更多→Dropdown（⋯） |
| 分页 vs 滚动 | 可核对/可排序→分页（页码+总数；页码多时省略号 1…5 6 7…20）；浏览型→无限滚动/加载更多；>1000 行→虚拟滚动 |
| 滚动位置 | 长列表加载更多/返回上一页时保持滚动位置；重置场景（切筛选）才回顶 |

## 4. 输入组件

| 组件 | 使用场景 | 坑 |
|---|---|---|
| TextField | 短文本单行（用户名/邮箱/搜索） | 标签常显；占位符只提示格式；前缀/后缀放单位/图标 |
| Textarea | 长文本（备注/描述） | 行数+字数上限；可伸缩 |
| Select | 选项多或空间紧 | 见 §3.2 下拉选型 |
| Combobox | 可输入可选（搜索+新建） | 无匹配允许输入要明确；键盘导航 |
| Radio Group | 单选 2~5 个 | >5 转下拉 |
| Checkbox | 多选/开关式选择 | 列表批量选配全选 |
| 数字输入 | 精确数值 | 步进器；货币/百分比格式 |
| 密码 | 打码+眼睛切换 | 强度要求→实时强度条 |
| DatePicker | 日期/范围/年月/日期时间 | 范围用 RangePicker；默认只给日期；月份用月面板；格式随 i18n |
| 上传 | 单文件→点击；批量→拖拽区；图片→缩略图预览 | 大文件要进度+取消+重传；拖拽区有"拖到此处"提示；**图片上传前压缩/格式转换（省流量）** |
| 搜索建议 | 输入即搜索/联想 | 防抖 300ms；建议下拉（远程搜索）；无结果→空状态（见 §8） |
| 自动填充语义 | 表单字段配 autocomplete（email/current-password/new-password/tel） | 浏览器/密码管理器靠 autocomplete 填充，别只写 name |
| 剪贴板/导出 | 复制文本/导出 CSV/JSON | 剪贴板 API 需用户手势触发；导出用 Blob+下载；成功反馈 toast |

**中文输入法坑（Vue 3）**：拼音输入过程中 v-model 会收到中间态（拼音字母），实时校验/计数会误判。处理：监听 compositionstart/end，在 compositionend 后再取最终值（或用带 composition 处理的 v-model 封装）。

## 5. 表单

### 5.1 表单布局

| 场景 | 布局 |
|---|---|
| 字段 ≤6 且简单 | 单列，从上到下 |
| 字段 7~12 有类别 | 分组卡片（每组标题+说明） |
| 字段 >12 或流程长 | **步骤条拆分**（每步 ≤8 字段，可回退，进度可见） |
| 双列 | 仅当字段短且关系强（姓名+电话）；禁止双列文字墙 |
| 操作栏 | 长表单→底部固定（提交+取消）；短表单→表单尾部 |
| 未保存离开 | 编辑页/长表单：离开/关闭/切路由时未保存 → 确认（保存/放弃/取消）；纯展示页不用 |
| 字段顺序 | 相关字段相邻；按用户填写流程排序（高频/必填在前）；不按后端字段顺序 |
| Enter 提交 | 表单内 Enter 触发主操作；**有 textarea 时 Enter 换行不提交**（需明确提交方式，如 Ctrl+Enter） |
| 表单 vs 弹窗表单 | 短表单（≤6 字段）可弹窗/抽屉承载（见 feedback.md）；主流程表单进页面 |

### 5.2 校验

**规则单一来源**：前端校验规则以**接口契约为准**，与后端一致；禁止前后端各自维护规则（如邮箱正则只定一处）。前端只执行展示层校验（格式），业务规则（库存/权限/金额）在后端（见 api.md）。

**锚点**：校验时机 = "减少干扰 vs 及时反馈"的平衡——必填在提交时（不打扰）、格式在失焦（不打断输入流）、强度/长度实时（用户期待即时反馈）。

| 时机 | 校验内容 | 规则 |
|---|---|---|
| 提交时 | 必填/业务规则 | 兜底；禁止只依赖此层 |
| 失焦时 | 格式类（邮箱/手机号） | 减少输入干扰 |
| 行内实时 | 长度/密码强度 | 即时反馈 |
| 首次提交后 | 全部字段 | 转为实时校验（提交一次后即时反馈） |
| 异步校验 | 唯一性（用户名/手机号） | 失焦时调接口；防抖；竞态丢弃过期响应 |

- 错误展示：字段下内联优先；跨字段→顶部汇总+锚点；阻塞→弹窗。
- 错误消失：修改即消失，不等下次提交。
- 必填标记：默认标"可选"；全必填不加星号。
- 禁止：每击键校验整个表单；提交中按钮可重复点击（见 §3.1 防重复）。**边界**：搜索框"输入即查询"（防抖）是查询不是校验，不受此限。
- 可访问性：错误用 aria-invalid + aria-describedby 关联到输入框。
- **提交失败定位**：提交校验失败 → 滚动到第一个错误字段并聚焦（配合顶部汇总锚点）。

**Vue 3 示例**（失焦校验 + 提交兜底）：

```vue
<script setup>
const email = ref('')
const emailError = ref('')
const onBlur = () => {
  if (email.value && !/^[^@\s]+@[^@\s]+$/.test(email.value)) {
    emailError.value = '邮箱格式不正确'
  } else emailError.value = ''
}
const onSubmit = () => { /* 必填/业务规则兜底 */ }
</script>
<template>
  <input v-model="email" @blur="onBlur" :aria-invalid="!!emailError" aria-describedby="email-err" />
  <p v-if="emailError" id="email-err" role="alert">{{ emailError }}</p>
</template>
```

## 6.3 进度条

**确定进度**（可估计时长/有百分比）：

| 场景 | 形态 |
|---|---|
| 上传/下载 | 平滑填充的线性进度 |
| 任务分多步 | 阶段步骤条（显示当前状态） |
| 强调完成度 | 圆环百分比 |
| 数据大屏 | 液体填充仪表 |

**不确定进度**（无法估计时长）：

| 场景 | 形态 |
|---|---|
| 信息同步 | 循环同步图标 |
| 搜索设备 | 雷达扫描动画 |
| 等待聊天回复 | 三点跳动 |
| 识别语音 | 音频波纹 |

**骨架屏（唯一权威定义）**：页面结构加载 → Skeleton 优先于 spinner（骨架预览内容形状）；骨架与真实内容形状一致。其余章节引用此处。

## 6.4 动效策略

| 场景 | 规则 |
|---|---|
| 页面/路由切换 | 过渡动画（淡入/滑动）≤300ms；非必要不加 |
| 列表增删 | 入列/离场动画说明数据变化；批量更新勿逐条动画 |
| 状态变化 | 新值高亮/闪烁一次；禁止持续动画 |
| 何时不用 | 高频刷新数据（轮询/实时流）禁用；尊重 prefers-reduced-motion |
| 原则 | 动画服务"解释状态变化"，不是装饰；微交互 ≤200ms，过渡 ≤300ms |

## 8. 状态与三态

**空状态（唯一权威定义）**：图标+文案+行动号召（"去添加第一个"/"清除筛选"）。其余章节引用此处。

| 状态 | 规则 |
|---|---|
| 加载态 | 骨架屏（见 §6.3）；局部加载用行内 |
| 错误态 | 说明原因+重试按钮+不丢已填数据 |
| 空状态 | 见上（唯一定义）。**区分两种空**：真无数据 → 引导创建；筛选/搜索无结果 → "清除筛选/重置"入口 |
| **局部失败** | 行级/区块级失败 → 局部重试+该行/块错误标识，**不整页重载**；全局失败 → 整页错误态 |

错误页（404/403/500）：图标+文案+唯一行动（返回首页/重试）。403 → 无权限提示（不泄露资源存在性）；401 登录态过期 → 跳登录页并回跳；500 → 刷新/稍后重试 + 必要时联系支持入口。与 api.md 错误分类保持一致。

**错误文案规范**：说人话 + 给原因 + 给行动（"网络开小差了，请重试"）；不暴露技术细节（状态码/堆栈）；语气中性不甩锅。
