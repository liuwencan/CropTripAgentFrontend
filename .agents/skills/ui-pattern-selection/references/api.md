# 接口对接

> 决策点索引：项目结构探测、接口复用优先、无法复用时的选项式提醒、瘦前端原则、数据获取模式（缓存/乐观更新/竞态/错误分类/取消/三态映射/离线）。🟡 启发级；"先问后写"为硬规则。

## 项目结构探测（不要假设）

- 先探测 API 组织约定：`src/api/`（按领域模块的 js，RuoYi/vue-element-admin 惯例）/ `src/services/` / composables 内嵌 / 请求库（axios/fetch 封装）。
- **按领域模块对应，不是页面一一对应**：一个页面调多个模块接口，一个模块 js 服务多个页面。
- 跟随既有惯例写新调用（同样的 request 封装、同样的返回处理）。
- **无惯例时**（全新项目无 api 目录）：默认建 `src/api/` 按领域模块（主流惯例），并写入 README 说明。

## 接口复用优先

- 写新功能前，先读对应领域的 API 模块，提取可用接口清单（路径/方法/参数/返回）。
- 同路径、同语义 → 直接复用，不新建。
- 语义接近但缺参数/字段 → 优先提议**扩展后端**（加可选参数/补返回字段）复用，而非新建。

## 无法复用时的提醒（带选项问用户）

1. 先展示：现有相关接口清单 + **缺口分析**（为什么复用不了：缺参数/缺字段/语义不同）。
2. 再带选项询问用户：
   - A. 扩展后端复用（加可选参数/补返回字段）——需后端配合
   - B. 新建接口——先给出**接口契约草案**（路径/方法/参数/返回），标注需后端实现，用户确认后才写前端
   - C. 用户手动决定
3. 原则：**先问后写**；新建接口默认先出契约草案，不直接写死前端。

## 瘦前端原则

- 业务逻辑/校验规则/数据聚合尽量后端实现；前端只做请求与展示。
- 前端只做展示层校验（格式）；业务规则（库存/权限/金额）必须在后端。

## 数据获取模式

| 决策点 | 规则 |
|---|---|
| 获取模式 | 页面加载拉取 vs 用户触发 vs 轮询 vs 实时（SSE/WebSocket）——按数据新鲜度要求选 |
| 缓存与失效 | 只读 GET 可缓存；实时/敏感不缓存；**提交后必须失效刷新**；缓存加 TTL/手动刷新 |
| 乐观更新 | 可回滚+延迟敏感 → 可用（失败回滚 + toast 告知）；**资金/不可逆操作禁止** |
| 竞态 | 搜索防抖/节流；过期响应丢弃（请求序号校验） |
| 错误分类 | 网络错误 vs HTTP 状态码 vs 业务错误码 → toast/内联/重试 不同展示；**403 → 无权限提示；401 → 跳登录**（与 SKILL.md §8 一致） |
| 请求取消 | 组件卸载/离开页面时取消进行中请求（AbortController），防卸载后更新状态 |
| 三态映射 | loading/error/empty 挂到请求生命周期（复用 SKILL.md §8） |
| 离线/弱网 | 弱网降级（降级缓存/简化渲染）；必要时 PWA 离线缓存 |

## 接口模块 Vue 3 示例（按领域组织）

```ts
// src/api/order.js —— 跟随项目既有 request 封装，按领域模块
import request from '@/utils/request'
export const getOrderList = (params) => request.get('/api/orders', { params })
export const createOrder = (data) => request.post('/api/orders', data)
export const updateOrderStatus = (id, status) =>
  request.put(`/api/orders/${id}/status`, { status })
```

新页面写调用前：先读同领域模块（接口复用优先）；无法复用 → 选项式询问。
